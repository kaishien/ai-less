### 💻 Cursor: что умеет агентный режим

Большинство используют Cursor как «умный автокомплит». На самом деле это агент, который умеет:

- Читать и изменять **несколько файлов** за один запрос
- Выполнять **терминальные команды** (тесты, линтер, git)
- Использовать **внешние инструменты** через MCP (БД, API, браузер)
- Помнить контекст проекта через **Rules** и **Skills**
- Реагировать на **события** через Hooks

**Разница между джуниорским и senior-использованием Cursor — насколько хорошо настроен контекст.**

---

### 📌 Cursor: Rules — постоянный контекст агента

**Что это:** Инструкции, которые всегда подставляются в контекст, не нужно повторять в каждом промпте.

**Три уровня:**

| Уровень | Где | Когда |
|---|---|---|
| User Rules | Cursor Settings → Rules | Личные предпочтения (язык, стиль ответов) |
| Project Rules | `.cursor/rules/*.mdc` | Стандарты команды, архитектурные решения |
| AGENTS.md | Корень проекта | Простой Markdown без frontmatter |

**Приоритет:** Team → Project → User → `.cursorrules` → AGENTS.md

---

### 📌 Cursor: Rules — пример для backend-проекта

```yaml
---
description: Python FastAPI стандарты проекта
globs: **/*.py
alwaysApply: false
---
# Технический стек
- Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.0 (async)
- Тесты: pytest + httpx AsyncClient

# Обязательные правила
- Только async функции в роутерах и сервисах
- Raise HTTPException, никогда не возвращать dict с ошибкой
- Без docstrings — только inline комментарии для неочевидной логики

# Запрещено
- Синхронные вызовы в async функциях (time.sleep → asyncio.sleep)
- Голые except: без указания типа исключения
```

> Заметьте разницу в качестве вывода до и после Rules на одном промпте.

### 📌 Cursor: Skills — повторяемые сценарии

**Что это:** Папки с `SKILL.md` — учат агента выполнять конкретные задачи по алгоритму.

**Где хранить:**
- Личные: `~/.cursor/skills/` — доступны во всех проектах
- Проектные: `.cursor/skills/` — версионируются в git, шарятся с командой

**Примеры сценариев:**
- Code review по стандартам вашей команды
- Генерация PR description в нужном формате
- Добавление метрик (Prometheus) к новому сервису
- Написание тестов по существующему паттерну в репозитории

> Skills — это «обученный» агент, которого можно передать новому члену команды.

---

### 📌 Cursor: Commands — слэш-команды

**Что это:** Команды, доступные через `/` в чате.

**Где хранить:** `.cursor/commands/` (проект) или `~/.cursor/commands/` (глобально)

**Практические примеры:**

```
/review    — код-ревью по стандартам команды
/test      — написать тест для выделенной функции
/explain   — объяснить модуль без пересказа кода
/commit    — коммит в стиле Conventional Commits
/perf      — найти узкие места в производительности
```

> Один файл — одна команда. Версионируются в git.

---

### 📌 Cursor: MCP — внешние инструменты агента

**Что это:** Model Context Protocol — стандарт подключения внешних инструментов к агенту.

**Как подключить:** Cursor Settings → Features → MCP → Add New MCP Server

**Готовые серверы (топ для разработчика):**

| MCP-сервер | Что даёт агенту |
|---|---|
| `github` | Читать PR, issues, репозитории |
| `postgres` / `sqlite` | Выполнять SQL-запросы напрямую |
| `playwright` | Управлять браузером, тестировать UI |
| `docker` | Управлять контейнерами |

> На дне 3 разберём MCP подробно и напишем свой сервер. Сейчас — понять идею.

### 📌 Cursor: Hooks — автоматизация событий

**Что это:** Шелл-команды, выполняемые до/после действий агента.

**Настройка:** `~/.cursor/hooks.json` или `.cursor/hooks.json` в проекте.

**Ключевые события:**

| Событие | Когда срабатывает |
|---|---|
| `preToolUse` | Перед вызовом инструмента агентом |
| `postToolUse` | После вызова инструмента |
| `beforeSubmitPrompt` | Перед отправкой промпта |

**Практические применения:**
- Запустить линтер после изменения файла агентом
- Логировать все действия агента
- Заблокировать запись в prod-директории (exit code 2 → отмена действия)

### 💬 Промпт-инжиниринг: почему это инженерная дисциплина

Плохой промпт → посредственный код → лишний код-ревью → потеря времени.

**Три уровня промптов в разработке:**

| Уровень | Где живёт | Когда используется |
|---|---|---|
| **Интерактивный** | Чат в IDE | Запрос здесь и сейчас |
| **Системный** | Rules / AGENTS.md | Постоянное поведение агента в проекте |
| **Production** | Код приложения | Промпты, которые работают в продакшене |

Сегодня разбираем уровни 1 и 2. Production-промпты — на неделях 2–3 (LangGraph).

### 💬 Анатомия хорошего промпта

```
[Роль]        Ты — senior Python-инженер, специализируешься на async системах.

[Контекст]    Проект: FastAPI-сервис обработки платёжных событий.
              Текущий модуль: src/payments/processor.py (приложен).

[Задача]      Добавь retry-логику с exponential backoff для вызовов
              внешнего payment gateway.

[Ограничения] - Используй tenacity (уже в requirements.txt)
              - Не меняй публичный интерфейс process_payment()
              - Логи через structlog (уже настроен)
              - Максимум 3 попытки, начальная задержка 1 сек

[Формат]      Верни только изменённый файл, без объяснений.
```

> Каждый элемент убирает неопределённость. AI не угадывает — выполняет.

### 💬 Техника: Chain-of-Thought для архитектуры

Не просите писать код сразу — попросите сначала объяснить подход.

**Плохо:**
```
Напиши мне систему кэширования для нашего API
```

**Хорошо:**
```
Нам нужна стратегия кэширования для FastAPI эндпоинтов с разными TTL.
Сначала опиши 3 подхода (in-memory, Redis, гибрид) с плюсами и минусами
для нашего случая: 50к RPM, данные меняются раз в минуту, 3 инстанса сервиса.
После того как я выберу подход — пиши код.
```

> Chain-of-Thought позволяет поймать архитектурные ошибки до написания кода.

### 💬 Техника: Few-Shot — покажи пример

Модель воспроизводит **паттерн**, а не изобретает стиль с нуля.

```
Напиши тест по этому шаблону из нашей кодовой базы:

async def test_create_user_success(client: AsyncClient, db: AsyncSession):
    response = await client.post("/users", json={"email": "a@b.com"})
    assert response.status_code == 201
    assert await db.get(User, response.json()["id"]) is not None

Теперь напиши тест для DELETE /users/{id}:
- успешное удаление (200)
- несуществующий ID (404)
- нет прав (403)
```

> Один хороший пример из вашей кодовой базы стоит трёх абзацев описания.

### 💬 Техника: Структурированный вывод

Когда результат нужно обработать программно — просите конкретный формат.

```
Проанализируй этот Python-файл и верни JSON:
{
  "issues": [
    {
      "line": <номер строки>,
      "severity": "critical" | "warning" | "info",
      "type": "security" | "performance" | "style",
      "description": "<что не так>",
      "suggestion": "<как исправить>"
    }
  ]
}
Только JSON, без markdown-блоков, без пояснений.
```

> Используется в агентах для передачи данных между шагами — разберём в неделях 2–3.

### 💬 Техника: Итеративный диалог

Не пытайтесь получить финальный результат одним промптом.

**Шаг 1** — основа:
```
Реализуй BatchProcessor: принимает корутины, запускает не более N одновременно.
```

**Шаг 2** — конкретный аспект:
```
Добавь retry с exponential backoff через tenacity. Максимум 3 попытки.
```

**Шаг 3** — edge case:
```
Что произойдёт если одна из задач завершится с KeyboardInterrupt? Исправь.
```

> Итерация быстрее, чем один огромный промпт, который нужно переписывать целиком.

### ⚠️ Антипаттерны: что замедляет работу с AI

| Антипаттерн | Почему плохо | Вместо этого |
|---|---|---|
| «Напиши мне всё приложение» | AI теряет фокус, код несвязный | Декомпозируй на модули |
| Принять код без проверки | AI уверенно делает ошибки | Всегда запускай и читай diff |
| Не давать контекст | AI придумывает архитектуру сам | Прикладывай связанные файлы |
| Переспрашивать одно и то же | Потеря времени | Вынести в Rules / Skills |
| Не версионировать Rules | Настройки теряются | `.cursor/rules/` в git |

### 🎉 Итоги дня

**Что взять с собой:**

- **Rules + Skills** — настройте под свой стек, AI будет следовать стандартам без напоминаний
- **Анатомия промпта** — роль, контекст, задача, ограничения, формат
- **Итерация > один большой промпт** — работайте диалогом
- **Few-shot из своей кодовой базы** — лучший способ задать стиль

**Следующее занятие:** LLM API в продакшене — стриминг, rate limits, GigaChat, YandexGPT.

> Инструмент становится полезным после 2–3 дней регулярного использования — не после одного занятия.
