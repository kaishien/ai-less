# День 3 (Неделя 1) • Практика: вайбкодинг — прототип без разработчиков

**Время:** 30–45 минут

Вашему отделу нужна внутренняя страница: каталог инструкций / форма опроса сотрудников / простой дашборд по продажам. Программистов выделят через месяц, а пилот нужен на этой неделе. Раньше единственным способом был сложный конструктор с ограничениями — теперь достаточно описать словами, и ИИ соберёт работающий прототип, который можно показать руководителю и собрать первую обратную связь.

---

## Шаг 1: Постановка задачи в одном экране (5 минут)

Хороший промпт для генерации интерфейса = аудитория + сценарий + 3–5 экранов + ограничения. Описывайте задачу так, будто заказываете дизайнеру.

**Что сделать:**

1. Выберите одну реальную задачу:
   - страница «Часто задаваемые вопросы» по новому продукту
   - форма опроса удовлетворённости сотрудников
   - мини-каталог инструкций / шаблонов / контактов отделов
   - дашборд-заготовка с метриками для еженедельного отчёта
2. Заполните шаблон постановки:

```
Что: ____________________________________________________
Для кого: _______________________________________________
Какой сценарий (3 шага): ________________________________
Какие экраны нужны (2–4): _______________________________
Что точно НЕ нужно: ____________________________________
Стиль (минимализм / корпоративный / яркий): ___________
```

**Пример заполнения:**

```
Что: внутренний каталог инструкций по охране труда
Для кого: новые сотрудники в первые две недели работы
Сценарий: 1) выбрать свой отдел 2) увидеть список инструкций 3) открыть PDF
Экраны: главная со списком отделов; страница отдела со списком документов
НЕ нужно: регистрация, авторизация, комментарии, лайки
Стиль: минимализм, цвета компании — синий и серый
```

---

## Шаг 2: Сборка прототипа в Lovable / Claude Artifacts (20 минут)

**Что сделать:**

1. Откройте один из инструментов:
   - **Lovable** (`lovable.dev`) — полноценное веб-приложение с базой данных
   - **Claude Artifacts** (`claude.ai`) — одна страница, без backend, идеально для статичного прототипа
   - **v0.dev** от Vercel — компоненты React, удобно для дашбордов
2. Отправьте промпт, собранный по шаблону:

```
Собери внутренний веб-интерфейс для [моей задачи из Шага 1].

Контекст:
- Аудитория: [из шаблона]
- Сценарий: [3 шага]
- Экраны: [перечисление]

Технические требования:
- Без авторизации
- Данные пока «захардкоженные» — массив из 10 примеров
- Адаптивная вёрстка (телефон + ноутбук)
- Стиль: [из шаблона]
- Русский язык интерфейса

Покажи готовый прототип, который можно открыть в браузере.
```

3. После первой генерации сделайте 2–3 уточнения через диалог:
   - «Добавь поиск по списку»
   - «Сделай шапку с логотипом компании»
   - «Добавь кнопку "Сообщить об ошибке" — открывает mailto»
4. Сохраните публичную ссылку на прототип / сделайте скриншоты

**На что обратить внимание:** не пытайтесь сразу получить «идеально». Лучше начать с грубого каркаса и итеративно докрутить через диалог — так же, как с дизайнером. Если ИИ запутался и каждая правка ломает что-то другое — откатитесь к предыдущей версии и сформулируйте запрос точнее.

---

## Шаг 3: Ограничения и риски (10 минут)

Прототип за 20 минут — это не production-система. Прежде чем показывать руководству или массово раскатывать, важно осознать, где границы.

**Что сделать:**

1. Откройте свой прототип и попробуйте «сломать» его:
   - Что будет если ввести 500 строк в поле?
   - Что будет если открыть с телефона?
   - Можно ли скопировать ссылку и открыть с чужого аккаунта (если задумывалось ограничение)?
   - Где хранятся данные? Уйдут ли они куда-то ещё?
2. Заполните таблицу — это ваш «протокол сдачи» для разговора с ИТ-отделом:

| Аспект | Прототип | Production (нужно от разработчиков) |
|---|---|---|
| Где хранятся данные | | |
| Кто видит данные | | |
| Аутентификация / SSO | | |
| Интеграция с 1С / SAP / Битрикс24 | | |
| Бэкапы | | |
| Уровень нагрузки | до 5 пользователей одновременно | |
| Стоимость владения | | |

3. Сформулируйте для себя: на каком этапе передать прототип в ИТ для «настоящей» разработки

**На что обратить внимание:** часто на этом этапе выясняется, что прототип закрывает 80% потребности и доводить его до production уже не нужно. Это нормально и означает, что вы сэкономили компании несколько недель работы команды.
