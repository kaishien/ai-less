# День 13 (Неделя 3) • Практика: обсуждение финального проекта (peer-to-peer)

**Время:** 30–45 минут (плюс 5–10 минут на подготовку дома)

Сегодня не делаем — проектируем. Это подготовка к демо-дням: завтра (четверг) и послезавтра (пятница). Артефакты этой сессии — постановка бизнес-задачи, выбранные инструменты, метрики, план выступления — должны быть готовы до того, как вы откроете любой ИИ-инструмент. Работа в формате peer-to-peer в группах до 3 человек: проговаривание идеи вслух обычно вскрывает 80% слабых мест ещё до того, как вы начнёте делать.

---

## Шаг 1: Постановка бизнес-задачи (10 минут)

Без чёткой задачи демо превращается в «я тут что-то поделал в нескольких инструментах». С чёткой — в «вот это сэкономит N часов в месяц».

**Заполните шаблон под свою задачу:**

```
Что за задача: ____________________________________________
Кто пользователь (с фамилией или ролью): __________________
Как часто возникает: ______________________________________
Сколько времени уходит сейчас (минуты в неделю): __________
Что НЕ работает в текущем процессе: _______________________
Что значит "получилось" (один результат): _________________
```

**Хорошие примеры задач:**
- «Каждую пятницу я полтора часа собираю отчёт по продажам в Excel и кидаю в Telegram. Хочу — за 5 минут.»
- «Раз в две недели я готовлю аналитику конкурентов по 8 источникам. Уходит день. Хочу — час.»
- «Каждое утро отдел поддержки тратит 30 минут на разбор почты по типам обращений. Хочу — автоматически в CRM.»

**Слабые формулировки задачи:**
- «Хочу использовать ИИ в работе» — нет конкретики
- «Хочу автоматизировать процессы в отделе» — слишком широко, какой именно процесс?
- «Хочу сделать чат-бота» — это решение, а не задача; какая боль за этим стоит?

## Шаг 2: Выбор инструментов из курса (10 минут)

Не нужно использовать всё. Хорошее решение часто = 1–2 инструмента + регламент.

**Заполните:**

| Этап решения | Какой инструмент | Почему этот |
|---|---|---|
| Получение данных | | |
| Обработка / анализ | | |
| Финальный артефакт (документ / письмо / отчёт) | | |
| Уведомление пользователя | | |

**Палитра инструментов из курса:**

| Тип задачи | Инструменты |
|---|---|
| Текст, саммари, классификация | ChatGPT / Нейрофонд / GigaChat / локальный Ollama |
| Поиск с источниками | Perplexity, NotebookLM |
| Транскрибация | Whisper, NotebookLM |
| Веб-интерфейс / прототип | Lovable, Claude Artifacts, Cursor |
| Автоматизация Google Workspace | Apps Script + ChatGPT |
| Workflow между сервисами | n8n |
| Боты в Telegram / на сайте | BotHelp, Salebot, Aimylogic |
| Картинки и креатив | Шедеврум, Kandinsky, Midjourney |
| Презентации | Gamma, Kimi, GigaChat |
| Многошаговые операции в браузере | Open Claw, Manus |

**На что обратить внимание:** меньше инструментов = надёжнее. Если в цепочке три отдельных сервиса, любой из них может сломаться — и весь процесс встанет. Где можно — заменяйте «два сервиса» на «один сервис с двумя действиями».

## Шаг 3: Метрики эффекта (10 минут)

Демо без цифр звучит как «мне это понравилось». С цифрами — как «компания сэкономит X».

**Заполните минимум три метрики:**

```
Метрика 1 (время):
Было: ___ минут на одну итерацию × ___ итераций в неделю = ___ мин/нед
Стало: ___ мин/нед
Экономия: ___ мин/нед × 52 недели = ___ часов в год

Метрика 2 (качество):
Что измеряем: количество ошибок / процент правок / скорость ответа
Было: ___
Стало: ___

Метрика 3 (масштаб):
Сколько людей смогут использовать: ___
Сколько часов сэкономит команда за месяц: ___
```

**Шаблон 5-минутного выступления (нужен на демо-дни):**

```
1 минута: контекст и задача
  "В нашем отделе X сотрудников тратят Y минут в день на Z."
  "Я хочу показать, как это можно сделать за W."

2 минуты: живая демонстрация
  Открываете ваш инструмент / прототип / автоматизацию,
  показываете один полный сценарий от запуска до результата.

1 минута: метрики
  Конкретные цифры "было/стало" по времени, качеству, масштабу.

1 минута: что дальше
  Что нужно от ИТ / руководства / команды, чтобы это масштабировать.
  Какие есть риски.
```

## Шаг 4: Peer-to-peer сессия (15 минут)

Соберитесь в группы по 2–3 человека. Каждый по очереди делает мини-питч на 2 минуты, остальные дают обратную связь по протоколу.

**Протокол обратной связи (4 пункта, 2 минуты каждому):**

```
1. Что в задаче понятно сразу: ________________
2. Что мне НЕ понятно после питча: ____________
3. Один риск, о котором я бы подумал: ________
4. Одно улучшение, которое я бы добавил: _____
```

**Правила:**
- Без оценок «нравится / не нравится». Только конкретика.
- Если идея слабая — лучше услышать это сейчас, чем перед руководством в пятницу.
- Записывайте обратную связь — потом легко забыть.

После каждого питча — 2 минуты на доработку плана с учётом обратной связи.

---

## Чеклист готовности к демо (четверг / пятница)

- [ ] Бизнес-задача сформулирована одной фразой, понятна неспециалисту
- [ ] Выбраны 1–3 инструмента из курса, есть обоснование «почему именно эти»
- [ ] Записаны 3 метрики «было / стало» с конкретными цифрами
- [ ] Готов 5-минутный сценарий выступления (1+2+1+1)
- [ ] Прошёл peer-to-peer сессию, получил минимум 3 пункта обратной связи
- [ ] Знаю, что покажу на экране (живой инструмент / прототип / автоматизация — не слайды!)

---

## Подсказки

**Идея слишком большая.**  
Урежьте до одной самой больной части. Лучше показать 30% задачи отлично, чем 100% наполовину.

**Нет хорошей идеи.**  
Возьмите задачу из соло-проекта недели 1 и расширьте на 2–3 шага вперёд. Или возьмите идею коллеги, который сегодня делал peer-to-peer с вами.

**Не уверен в метриках.**  
Замерьте на одной итерации старым способом и новым — этого достаточно для базовых цифр. Не нужно проводить полноценное A/B-исследование.

**Хочу сделать ещё одну фичу.**  
Запишите в stretch goals и не трогайте до пятницы. В четверг базовый сценарий должен работать стабильно — иначе на демо случится «у меня вчера работало».
