# День 7 (Неделя 2) • Практика: бот первой линии поддержки

**Время:** 30–45 минут

Отдел поддержки тонет в одинаковых вопросах: «как сбросить пароль», «когда зарплата», «где скачать инструкцию по командировкам». 80% обращений — типовые, ответы давно есть в базе знаний, но сотрудники всё равно пишут в чат. Сегодня вы спроектируете и соберёте каркас бота, который снимет половину рутинной нагрузки и научится передавать оператору только то, что бот не понял.

---

## Шаг 1: Сценарий диалога с ветвлением (15 минут)

Бот без сценария = бот, который раздражает пользователя. Начинаем с того, чтобы расписать «дерево» — какие вопросы он понимает и куда уводит дальше.

**Что сделать:**

1. Выберите свой отдел или знакомую вам тему. Соберите 8–10 типовых вопросов из реальной практики
2. Сгруппируйте их в 3–4 «корневых» темы (например: пароли, отпуска, командировки, оборудование)
3. Нарисуйте сценарий на бумаге или в Miro / FigJam по схеме:

```
Старт: «Здравствуйте! Я бот отдела HR. Чем могу помочь?»

  → Пароли и доступы
      → Сбросить корпоративный пароль
      → Забыл логин
      → VPN не работает → передать оператору (тег: ИТ)

  → Отпуска и больничные
      → Сколько осталось дней отпуска
      → Как оформить
      → Перенос отпуска

  → Командировки
      → Лимит на отель / суточные
      → Авансовый отчёт

  → Другое → собрать вопрос текстом → передать оператору
```

4. Для каждой ветки определите:
   - **Текст ответа** (3–5 предложений, без воды)
   - **Ссылка на инструкцию** (PDF или страница в Confluence)
   - **Кнопки** — что предложить нажать дальше
   - **Условие эскалации** — когда передать живому оператору

**Шаблон для одной ветки:**

```
Вопрос пользователя: "сколько у меня осталось дней отпуска"
Что бот делает:
1. Уточняет ФИО или табельный номер
2. Отвечает: "Согласно учёту, у вас N дней основного + M дней дополнительного"
3. Предлагает 3 кнопки: «Подать заявление» / «Перенести» / «Связаться с HR»
Эскалация: если пользователь пишет "это неправильно" или "я не согласен" → передать оператору с тегом "спор по отпускам"
```

**На что обратить внимание:** хороший бот всегда даёт кнопку «связаться с человеком» — без неё пользователи начинают воевать с роботом и плохо относятся ко всему отделу.

## Шаг 2: Сборка в конструкторе (15 минут)

Сегодня не пишем код — берём готовый конструктор. Большинство из них на бесплатных тарифах позволяет собрать каркас за полчаса.

**Что сделать:**

1. Выберите один конструктор:
   - **BotHelp** (`bothelp.io`) — российский, удобный визуальный редактор, есть бесплатный тариф
   - **Salebot** (`salebot.pro`) — российский, более продвинутый
   - **Aimylogic** (`aimylogic.com`) — Tinkoff, для голосовых и текстовых ботов
   - **ManyChat** — для соцсетей (если ваш бот для Telegram + Instagram)
2. Создайте новый бот, подключите тестовый Telegram-канал (бот создаётся через `@BotFather` за 2 минуты)
3. Реализуйте **одну** ветку сценария целиком (например, «отпуска»):
   - Стартовое сообщение
   - Кнопки выбора темы
   - 2–3 финальных ответа с ссылками
   - Кнопка «связаться с человеком» — отправляет уведомление в служебный чат

**На что обратить внимание:** не пытайтесь сразу запихнуть все 4 ветки. Полностью работающая одна ветка лучше четырёх «недоделанных». Когда одна работает — копирование и адаптация остальных занимает 10 минут.

## Шаг 3: Эскалация и сценарий «бот не понял» (10 минут)

Любой бот рано или поздно встречает вопрос, который не вписывается в сценарий. От того, как он себя ведёт в этой ситуации, зависит общее впечатление.

**Что сделать:**

1. В конструкторе настройте **fallback** — что происходит, когда пользователь ввёл текст вне сценария:
   - Не пытайтесь угадать — это раздражает
   - Лучше: «Я пока не умею это решать, передаю человеку. Опишите задачу одним сообщением — оператор ответит в течение [N часов]»
   - Сохраняйте обращение в журнал — потом разберёте, какие новые ветки добавить
2. Настройте уведомление оператору:
   - При эскалации — сообщение в служебный чат (Telegram-группа отдела)
   - В сообщении: ФИО пользователя, тема, его последний вопрос, ссылка на чат с ним
3. Протестируйте 3 сценария:
   - **Штатный** — пользователь идёт по сценарию, получает нужный ответ
   - **Граничный** — пользователь нажимает не то, что задумано (например, сразу пишет вопрос вместо кнопки)
   - **Отказ** — пользователь пишет вопрос вне темы → бот корректно эскалирует

**На что обратить внимание:** записывайте все вопросы, на которые бот ответил «не понял». Через неделю это идеальный список «что добавить в сценарий».

## Шаг 4 (опционально): Интеграция с базой ответов (5 минут)

Если у вас есть Confluence / Notion / Google Docs с инструкциями — бот может искать ответ в них автоматически через RAG. Это уровень «продвинутый бот» и обычно подключается отдельно.

**Что посмотреть:**
- **BotHelp + GPT** — встроенный режим «ответ из базы знаний»
- **n8n + ChatGPT + векторная база** — следующий день курса
- **Custom GPT** в ChatGPT — загрузите PDF-инструкции и бот будет отвечать из них (но это вне Telegram)

Не нужно делать сегодня — главное понимать, что путь развития есть.

---

## Итог дня

Через 30–45 минут у вас должно быть:
- Нарисованный сценарий бота с 3–4 ветками, 8–10 вопросами
- Одна ветка сценария собрана в конструкторе и работает в реальном Telegram
- Настроена эскалация оператору с уведомлением
- Проведены 3 теста: штатный, граничный, отказ
