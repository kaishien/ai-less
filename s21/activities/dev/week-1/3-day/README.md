# День 3 • Практика: RAG от индексации до ответа

Вы — backend-инженер в стартапе. Команда хочет добавить в корпоративный портал поиск по внутренней документации: политики, инструкции, FAQ. Документов ~200 страниц, они обновляются раз в неделю. Задача: построить RAG-пайплайн с нормальным chunking, индексацией в Qdrant и endpoint'ом для вопросов.

Используйте синтетический набор документов из `s21/code/week-1/3-day/docs/`.

```
rag-service/
  indexer.py     # Chunking + embedding + загрузка в Qdrant
  retriever.py   # Поиск + score threshold
  main.py        # FastAPI endpoint
  .env
```

## Релиз 0: Эмбеддинги — понять, как работает

Прежде чем строить пайплайн, разберитесь с тем, что происходит внутри.

**Задание:**
1. Установите зависимости: `openai`, `numpy`
2. Получите эмбеддинги для 5–6 фраз: похожих по смыслу, похожих по словам, и несвязанных
3. Вычислите cosine similarity между всеми парами
4. Выведите матрицу сходства и найдите самую неожиданную пару (высокое сходство у разных по словам фраз или низкое у похожих)

**Пример фраз для эксперимента:**
```python
phrases = [
    "Как подключиться к VPN?",
    "Инструкция по настройке VPN",
    "Корпоративная виртуальная частная сеть",
    "Как сбросить пароль?",
    "Политика отпусков сотрудников",
    "Vacation policy for employees",
]
```

**Промпт:**
```
Напиши скрипт: получи эмбеддинги для списка phrases через OpenAI text-embedding-3-small.
Вычисли cosine similarity для всех пар через numpy.
Выведи матрицу сходства в виде таблицы (фразы по осям, значения с 2 знаками).
```

## Релиз 1: Индексация документов

Реализуйте `indexer.py` — chunking, embedding, загрузка в Qdrant.

**Задание:**
1. Запустите Qdrant локально: `docker run -p 6333:6333 qdrant/qdrant`
2. Реализуйте `recursive_split(text, chunk_size=512, overlap=50)` — делит по абзацам, потом по предложениям, если не влезает
3. Добавьте метаданные к каждому чанку: имя файла, номер чанка, дата документа
4. Загрузите чанки в Qdrant батчами (не по одному — экономит время и деньги на embedding)
5. Проверьте: убедитесь через Qdrant UI (`localhost:6333/dashboard`), что векторы появились

**Промпт:**
```
Напиши indexer.py для Qdrant:
1. Функция recursive_split(text, chunk_size=512, overlap=50) — сначала по \n\n, потом \n, потом . 
2. Функция index_documents(docs: list[dict]) — где каждый doc = {text, source, date}
3. Эмбеддинг батчами по 100 чанков через openai text-embedding-3-small
4. Upsert в Qdrant коллекцию "docs", payload = {text, source, date, chunk_id}
```

## Релиз 2: Retrieval + генерация

Реализуйте `retriever.py` и endpoint `POST /ask`.

**Задание:**
1. Реализуйте `search(query, k=4, threshold=0.75)` — возвращает релевантные чанки или пустой список
2. Если результатов нет — endpoint возвращает `{"answer": "Информация не найдена в базе знаний.", "sources": []}`
3. Если есть — передаём чанки в LLM с промптом: «Отвечай только на основе контекста, не придумывай»
4. В ответе возвращайте `{"answer": "...", "sources": ["docs/vpn.md", ...]}` — уникальные источники
5. Проверьте граничный случай: задайте вопрос не по теме документов — должен вернуться fallback

**Промпт:**
```
Напиши retriever.py и FastAPI endpoint POST /ask.
search() делает Qdrant query_search с limit=k, фильтрует по score >= threshold.
System prompt для LLM: "Ты — корпоративный ассистент. Отвечай ТОЛЬКО на основе
предоставленного контекста. Если ответа в контексте нет — скажи об этом явно."
Возвращай {answer: str, sources: list[str]} где sources — уникальные source из payload.
```

## Релиз 3: Сравнение стратегий chunking

Запустите эксперимент — измерьте, как chunk_size влияет на качество retrieval.

**Задание:**
1. Создайте три коллекции в Qdrant: `docs_256`, `docs_512`, `docs_1024`
2. Проиндексируйте одни и те же документы с разным `chunk_size` (overlap везде 10%)
3. Задайте 5 тестовых вопросов, запишите ответы и `top score` из каждой коллекции
4. Составьте вывод: при каком размере чанка ответы точнее для ваших документов?
5. Найдите вопрос, где маленький чанк плохо справляется (ответ разрезан), и вопрос, где большой чанк хуже (шум)

**Промпт:**
```
Напиши скрипт compare_chunks.py:
1. Индексирует docs в три коллекции Qdrant с chunk_size 256, 512, 1024 (overlap = 10%)
2. Принимает список вопросов QUESTIONS и для каждого делает поиск в трёх коллекциях
3. Выводит таблицу: вопрос | top-1 score 256 | top-1 score 512 | top-1 score 1024 | топ-текст 512
Запусти на 5 разных вопросах и сделай вывод какой chunk_size лучше для данных документов.
```
