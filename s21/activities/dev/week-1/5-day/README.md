# Соло-проект • Неделя 1 — Корпоративный поиск по документации

**Формат:** самостоятельная работа, без преподавателя  
**Время:** ~6 часов  
**Результат:** MCP-сервер, подключённый к Cursor — агент отвечает на вопросы по внутренней документации компании

---

## Контекст

Компания «ТехноКорп» накопила внутреннюю документацию: политики, инструкции, onboarding-гайды. Сотрудники теряют время на поиск — нужен AI-ассистент, который отвечает на вопросы по этим документам.

Задача: построить RAG-пайплайн поверх набора Markdown-документов и обернуть его в MCP-сервер, чтобы Cursor Agent мог использовать его как инструмент.

---

## Архитектура

```
Cursor Agent
     │
     │  MCP tool call: search_docs(query="Как настроить VPN?")
     ▼
MCP Server (FastMCP, stdio)
     │
     ├── embed(query)  ──►  OpenAI text-embedding-3-small
     ├── search(vector)  ──►  Qdrant
     │                           └── возвращает top-k chunks + metadata
     └── возвращает список {text, source, score}
     │
     ▼
Cursor Agent собирает ответ и цитирует источники
```

Опционально — второй инструмент `answer_question(query)`, который сам вызывает LLM с найденным контекстом и возвращает готовый ответ.

## Вехи

### Веха 1: Индексация работает

Запустите `python indexer.py` — документы загружены в Qdrant.

**Готово когда:**
- `python indexer.py` завершается без ошибок
- В Qdrant Dashboard (`localhost:6333/dashboard`) видна коллекция `technocorp-docs` с векторами
- Количество точек соответствует ожидаемому количеству чанков

**Проверочный скрипт:**
```python
from qdrant_client import QdrantClient
client = QdrantClient("localhost", port=6333)
info = client.get_collection("technocorp-docs")
print(f"Vectors: {info.vectors_count}")  # должно быть > 0
```

---

### Веха 2: Retrieval работает

Поиск возвращает релевантные фрагменты с источниками.

**Готово когда:**
- На запрос `"Как подключиться к VPN?"` — возвращается чанк из `vpn-setup.md`, score > 0.75
- На запрос `"Сколько дней отпуска?"` — возвращается чанк из `leave-policy.md`
- На нерелевантный запрос (`"Рецепт борща"`) — возвращается пустой список или score < порога

**Проверочный скрипт:**
```python
results = search("Как подключиться к VPN?", k=3, threshold=0.75)
for r in results:
    print(r["source"], r["score"], r["text"][:100])
```

---

### Веха 3: MCP-сервер запускается

FastMCP-сервер с инструментом `search_docs` работает в MCP Inspector.

**Готово когда:**
- `npx @modelcontextprotocol/inspector python server.py` открывается в браузере
- Инструмент `search_docs` виден в списке
- Вызов через Inspector возвращает результаты

---

### Веха 4: Подключено к Cursor

Cursor Agent использует ваш сервер для ответов на вопросы.

**Готово когда:**
- Конфиг в `~/.cursor/mcp.json` добавлен, Cursor перезапущен
- В Agent-режиме запрос `"Найди в документации как настроить VPN"` вызывает ваш инструмент
- Агент цитирует источник (`vpn-setup.md`)

## Требования к реализации

**Обязательно:**
- [ ] Chunking с overlap (рекомендуется `chunk_size=512, overlap=50`)
- [ ] Метаданные в каждом чанке: имя файла-источника, номер чанка
- [ ] Score threshold в retrieval — не возвращать нерелевантные результаты
- [ ] Обработка ошибок в MCP-инструменте: ошибка как строка, не как исключение
- [ ] Docstring у каждого MCP-инструмента объясняет агенту когда его использовать

**Формат возврата `search_docs`:**
```python
[
    {
        "text": "...",
        "source": "vpn-setup.md",
        "score": 0.89,
        "chunk_id": 3
    },
    ...
]
```

## Stretch goals

Если основные вехи пройдены раньше времени:

**+Инструмент `answer_question(query)`**
Вызывает `search_docs`, затем отправляет найденный контекст в LLM и возвращает готовый ответ со списком источников. Агент выбирает этот инструмент когда нужен прямой ответ, а не сырые фрагменты.

**+Фильтрация по источнику**
Добавьте параметр `source_filter: str | None` в `search_docs` — искать только в конкретном документе. Тогда агент может отвечать на: `"Найди в политике отпусков..."`.

**+Resource с индексом документов**
MCP Resource `technocorp://docs` возвращает список всех документов с датой и количеством чанков. Агент видит что вообще есть в базе знаний.

**+Инкрементальная переиндексация**
`indexer.py --file docs/new-policy.md` — добавляет только новый документ, не переиндексирует всё.

## Подсказки

**Qdrant не запускается:**
```bash
docker run -p 6333:6333 -p 6334:6334 qdrant/qdrant
```

**Embedding дорого / медленно при разработке:**
Закешируйте эмбеддинги в файл при первом запуске — пересчитывайте только при изменении документов.

**MCP Inspector не видит инструменты:**
Убедитесь что `mcp.run()` вызывается внутри `if __name__ == "__main__"`. FastMCP пишет в stdout — не добавляйте туда `print()` для отладки, используйте `sys.stderr`.

**Агент не вызывает MCP-инструмент:**
Перепишите docstring более конкретно. Плохо: `"Поиск по документам"`. Хорошо: `"Ищи этот инструмент когда нужно найти информацию во внутренней документации компании ТехноКорп"`.

**Получаете нерелевантные результаты:**
Попробуйте снизить `chunk_size` до 256 — длинные чанки размывают эмбеддинг. Или поднять threshold до 0.80.

На следующей неделе (понедельник, первые 10 минут) — демо в 2 минуты:

1. Показать Qdrant Dashboard с заполненной коллекцией
2. Задать агенту в Cursor один вопрос по документации — агент вызывает MCP-инструмент и отвечает с источником
